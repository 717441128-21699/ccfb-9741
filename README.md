# 银企 RPA 自动下载与对账系统（全本地仿真）

集团财务每日需登录多家银行网银下载回单/流水、再与 ERP 收付款逐笔核对。本项目用
**Python + Playwright + Flask** 实现全流程自动化，所有银行站点均为本地仿真，
**不接触任何真实网银**。

## 一、能力对照

| 需求 | 实现 |
| --- | --- |
| 5 家银行、22 个账户，登录方式/页面各异 | 仿真站：账号密码、U 盾证书、短信验证码、扫码四种登录，5 套 DOM |
| 会话超时 | 各账户独立超时（2~12 分钟），机器人检测到踢回登录页自动重登续跑 |
| PDF 回单 / CSV / OFX 流水 | 三种格式构建器 + 解析器，五家银行回单版式、三种 CSV 列布局、SGML-OFX |
| 偶发下载失败 | 仿真站按哈希确定性注入约 14% 首次失败，机器人每文件重试 3 次 |
| 按账户+日期区间下载，中断续传、不重复下载 | `download_files` 唯一键 + 文件哈希，重跑自动跳过已成功文件 |
| 统一流水结构、金额日期格式统一 | `ingest/parsers.py` + `common` 归一化（千分位/￥/万/括号负数、8 种日期） |
| 回单与流水重复出现去重 | 按 `(账户, 银行流水号)` 合并，来源标签同时保留 |
| 与 ERP 按金额/日期/户名/摘要匹配，支持一对多、多对一 | 1:1 加权评分 → 组合子集搜索，尾差 0.10 元、日期窗口 2 天 |
| 户名简写、尾差 | 户名字符相似度（子串/ Jaccard）、金额分桶容忍 |
| 对不上的人工处理，处理过不再报 | 异常页人工匹配/忽略，写指纹表 `manual_resolutions`，跨轮次复用 |
| 每步截图留痕、失败单独重跑 | 关键步骤截图入 `screenshots/`，任务页可看日志/截图、可单任务重跑 |
| 自动对账率 ≥ 95%，剩余全部可见 | 一键演示脚本自动校验指标并输出结论 |

## 二、目录结构

```
bank_rpa/
├── config.py                 # 路径/端口/对账参数
├── db.py                     # SQLite 表结构与访问层
├── common/                   # 金额、日期、户名、摘要归一化
├── data_gen/                 # 测试数据 + ERP xlsx 生成（6 种业务场景）
├── banksim/
│   ├── builders.py           # CSV/OFX/PDF 文件构建（各银行版式）
│   └── server.py             # 5 家仿真网银 Flask 站点（含超时/故障注入）
├── rpa/
│   ├── flows.py              # 各银行页面选择器与登录流程
│   └── bot.py                # Playwright 机器人（重试/续传/重登/截图）
├── ingest/
│   ├── parsers.py            # PDF/CSV/OFX → 统一交易字典
│   └── pipeline.py           # 解析入库 + 去重合并
├── reconcile/engine.py       # 对账引擎 + 人工处理
├── web/                      # 对账后台（5 页面 + 后台作业线程）
└── cli.py                    # 命令行 / 一键演示
tests/                        # pytest：归一化、三格式往返、对账场景、人工记忆
```

## 三、快速开始（Windows / Python 3.12）

```powershell
py -3.12 -m pip install -r requirements.txt
py -3.12 -m playwright install chromium

# 一键全流程（生成数据 → 起仿真站 → RPA 下载 → 解析去重 → 对账 → 指标校验）
$env:BANK_RPA_HEADLESS="1"
py -3.12 -m bank_rpa.cli demo

# 或分步运行
py -3.12 -m bank_rpa.cli generate     # 1. 造数据
py -3.12 -m bank_rpa.cli bankweb      # 2. 仿真网银  http://127.0.0.1:5001
py -3.12 -m bank_rpa.cli admin        # 3. 对账后台  http://127.0.0.1:5000
# 网页「下载任务」页：一键批量下载 → 解析入库 → 对账结果页运行对账 → 异常页处理

py -3.12 -m bank_rpa.cli test         # 单元测试
```

环境变量：`BANK_RPA_HEADLESS=1` 无头浏览器（默认有头，便于观察）、
`BANK_RPA_BANK_PORT` / `BANK_RPA_WEB_PORT` 改端口、`BANK_RPA_DATA` 改数据目录。

## 四、后台五个页面

1. **账户配置**：22 个账户、银行、登录方式、超时、下载进度、启用/停用
2. **下载任务**：单账户/批量建任务，任务状态与进度，逐步日志与截图，失败单独重跑，解析入库按钮
3. **流水库**：统一流水查询筛选，回单/流水来源标签（去重后同笔合并）
4. **对账结果**：自动匹配率、规则分布、逐组明细与差额（精确/尾差/一对多/多对一/人工）
5. **异常处理**：银行单边/ERP 单边两栏勾选，人工匹配（支持多对）、忽略，人工记忆列表

## 五、测试数据场景（确定性随机种子，可复现）

精确匹配、尾差（0.01~0.08 元）、户名简写（如「上海云海国际贸易有限公司」↔「云海贸易」）、
摘要改写、一对多（拆分收付款）、多对一（合并到账/扣款）、银行单边、ERP 单边。

## 六、安全边界

- 全部站点、账号、文件、ERP 数据均为本地仿真生成，代码中不存在任何真实银行地址
- 仿真站页面带有显式「本地仿真环境 · 禁止用于真实业务」标识
- 截图仅存本地 `data/screenshots/`，不向外部网络发送任何数据
